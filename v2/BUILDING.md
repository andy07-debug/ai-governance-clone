# Building v2 screens (AI Governance demo replica)

Goal: recreate screens from the demo recording **with exact text and numbers** and a close visual match.
Source frames: `demo/frames/f_NNNNNN.jpg` (3024x1726, Retina 2x of a 1512x863 CSS viewport; NNNNNN/2 = seconds).
Section frame lists + narration: `demo/sections/<id>.md` (settled states, in time order).

## What already exists (do not touch)
- The app shell (dark Appmod.AI header, narrow empty AskMod chat panel, breadcrumb bar with home icon,
  fullscreen icon) is generated by `v2/build_v2.py` from the real captured app. You only build the
  **right-panel content below the breadcrumb bar** (frame region x≈620..3024, y≈280..1726 at the top scroll).
- `v2/router.js` — do not edit. Wire behaviour with attributes (below).

## Files you write
- `v2/screens/<screen-id>.html` — first line `<!-- title: <breadcrumb title> -->`, then the content.
  Wrap content in `<div class="px-5 pt-5 pb-6">…</div>` (or whatever padding the frame shows).
  The content area is `#screen` (scrolls vertically); it is 1209 CSS px wide at the demo viewport.
- `v2/overlays/<overlay-id>.html` — drawers/modals: include your own fixed backdrop + panel, e.g.
  `<div data-backdrop class="fixed inset-0 z-50 bg-slate-900/40 flex justify-end"><aside class="w-[560px] h-full bg-white overflow-y-auto">…</aside></div>`
- Images you crop from frames (logos, avatars, complex icons) → `v2/assets/<section>-<name>.png`, referenced as `src="assets/<file>"`.
  Prefer inline SVG (lucide-style, stroke 2) for normal UI icons.

## Behaviour attributes (handled by router.js)
- `data-go="<screen-id>"` navigate · `data-open="<overlay-id>"` open overlay · `data-close` close overlay
- `data-tab="<group>:<panel>"` + `data-panel="<group>:<panel>"` (use `hidden` on inactive panels);
  tab buttons carry `data-active-class` / `data-idle-class` (space-separated class lists to swap).
- `data-toggle` + `aria-checked`/`aria-pressed` + `data-on-class`/`data-off-class` for switches.
- Charts: `<canvas data-chart='{"type":"line","data":{…},"options":{…},"_yFormat":"usd0","_tooltipFormat":"usd2"}'></canvas>`
  inside a sized wrapper (`<div class="relative h-[140px]">`). Chart.js 4.5.1. Formats: usd, usd0, usd2, k, pct, int.
  Hide what the demo hides (legend/grid/ticks), match colours, `tension` for smooth curves, `fill` + gradient-like
  `backgroundColor` (rgba). Use exact values when readable; otherwise trace the curve shape from the frame.

## Styling
Tailwind v3 utility classes (compiled at build time, arbitrary values like `text-[13px]`, `bg-[#fdf2f2]` are fine).
Font: Inter (already default inside #screen). Measure from frames: CSS px = frame px / 2. Sample colours from
frame pixels with PIL rather than guessing.

## Build + compare loop (use YOUR label for a private build — never write clone/)
    python3 v2/build_v2.py --out <label>
    python3 v2/tools/shot.py <screen-id> --html v2/out/<label>/index.html --ref demo/frames/f_000013.jpg
    python3 v2/tools/shot.py <screen-id> --html v2/out/<label>/index.html --ref <frame> --scroll 700   # lower part
    python3 v2/tools/shot.py <screen-id> --html v2/out/<label>/index.html --ref <frame> --crop 620,280,1800,1000  # zoom
    python3 v2/tools/shot.py <screen-id>+<overlay-id> --html … --ref <frame>   # with an overlay open
`*-cmp.png` = replica (left) vs demo (right). Fix differences, re-run. Page errors are printed — keep them at none.

## Keep usage low
Read only the frames you need; crop to the region you're working on instead of reading whole frames;
2–3 compare iterations per screen is enough. Text and numbers must be exact; sub-pixel layout need not be.
